> 后续适配更新：歌曲海已通过首页会话初始化恢复搜索和音频解析，四个样本音频来自酷我 CDN，保留在酷我平台下。力音的旧播放接口不可用，当前适配为前往源站使用网盘下载，不作为音频直链播放。咪咕补测其他歌手与歌曲仍解析失败，暂时停用；这不代表平台永久停止服务。

检测日期：2026-10-22（Asia/Shanghai）。范围为当前 Web 注册的 12 个入口及其隐藏解析线路；桌面注册入口与平台映射相同，具体运行结果本次未另跑桌面程序。

## 检测方法与边界

直接加载仓库当前 TypeScript provider 实现，执行真实联网搜索与解析。每个入口搜索“晴天”“稻香”，每个关键词取一条结果解析；QQ、酷狗、网易云、波点的解析器逐个直接调用，避免自动回退掩盖失败。共 24 次搜索、36 次解析，18 次解析后拿到通过文件头检查的音频。补测咪咕每个关键词另外两条 Live 结果，以及力音的播放接口；对失败第三方接口补做直连检查。

音频检查使用 Range 请求并读取少量文件头，确认 MP3/FLAC 等实际内容，没有完整下载、浏览器播放或跨域下载验证。本机通过不代表机房 IP 通过；本次没有连接部署服务器。90svip 的服务器不可用来自用户反馈，未独立复核。失败为当前环境和样本的检测结果，不等于永久停服；XCVTS 有明确的下架提示。

### 映射证据与限制

- 煎饼的四个平台映射由 provider 注册参数、真实返回中转 URL 的 type 及 ID、最终音频 CDN 三方面核对。四个入口来自同一家第三方服务，不代表四家独立供应商。
- 波点搜索与天宝解析均直接调用酷我域名。“天宝”是现有代码的线路名称，不是另一家音乐平台或独立第三方 API。
- QQMP3 的当前站点标题为“米兔音乐”，站点前端同样调用 `/api/kw.php`；本次两个样本最终来自 `car-er.kuwo.cn` / `car-lv.kuwo.cn`。其搜索结果 rid 是站内 ID，不能因字段名 rid 就直接当作酷我曲目 ID。搜索数据库的完整来源无法由外部调用确认，但当前音频解析链路可以归入酷我。
- 力音“晴天”“稻香”的首批歌曲、歌手、数字 ID 与波点及煎饼酷我完全一致，例如 228908、440613。支持将搜索侧归为酷我。后续确认官网主要提供网盘下载，歌曲页残留音频链接已过期，因此采用源站网页交接，不声称恢复了音频直链。
- 歌曲海采用自有站内 ID。初测因会话初始化缺失遭 403；完成适配后，四个样本最终来自酷我 CDN，因此归入酷我。其站内搜索数据库的完整来源仍不可见，不能由四个样本推断全部曲库来源。
- 第三方服务内部是否再次调用其他解析供应商不可见；本报告确认的是项目直接请求的服务、公开响应与可验证的音乐平台归属。

## 重组菜单时的建议

一级采用网易云、QQ音乐、酷狗音乐、酷我音乐、咪咕音乐；二级展示具体线路，并保留机器可识别的 channelId。

建议初始启用：网易云的“官方搜索 + Meting”“煎饼”；QQ 的“官方搜索 + VKeys”“煎饼”；酷狗的“煎饼”，90svip 标记为本地通过、服务器受限；酷我的“波点 + 天宝”“米兔 / QQMP3”“煎饼”“歌曲海”，以及仅源站网盘下载的“力音”。咪咕一级平台保留，暂不提供可选渠道。上述均需在真实部署服务器补测后决定默认顺序。

XCVTS 标记下架；CYAPI、Baka、尘归归三个平台接口、海棠暂禁用。力音改为源站网盘下载。歌曲海已适配首页会话，恢复使用。

当前存在两个模型层面的问题，调整 UI 时需要一起处理：

1. 搜索渠道与音频解析器是不同维度。官方搜索加 VKeys/90svip/尘归归等线路会复用同一套搜索；煎饼和 QQMP3 则使用自己的搜索与解析组合。界面仍可统一显示为平台下的线路，但数据模型要明确 searchSource 与 resolver。
2. QQ、酷狗的 selectedParser 目前只调整尝试顺序，失败后继续回退其他解析器；网易云和波点也有内部自动回退。用户明确点选线路后，应该只尝试该线路，或显式开启“自动切换”，并返回实际命中的线路和失败原因。否则无法准确判断用户指定的渠道是否可用。

音质选项也应按线路能力展示。比如当前网易云将多种高音质统一映射为 Meting 的 br=2000，并不能由菜单上的 Hi-Res 等名称保证真实返回相应音质。

## 未启用的历史代码

`src/lib/providers/impl` 仍有爱听（2t58）、布谷（buguyy）、歌曲宝（gequbao）、JOOX（wjhe）的实现文件，但它们不在当前 provider 注册表及界面入口中。本次未将这些历史文件视为已启用渠道，也没有复测其在线状态。JOOX 的历史代码明确请求 `/api/music/joox/...`，不属于当前计划的五个平台；其余几个实现仅凭现有代码不能可靠认定单一底层平台。
